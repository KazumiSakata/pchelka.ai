# Внесение изменений

1. Создайте ветку от main.
2. Запустите `python server.py`; основной интерфейс находится в `public/`.
3. Измените минимальный набор файлов. Не добавляйте личные товары, секреты и результаты сборки.
4. Выполните проверки из README и проверьте сценарий в браузере.
5. Обновите документацию при изменении полей, источников данных, сетевых обращений и лимитов.
6. Создайте pull request с описанием поведения и результатов проверки.

Не меняйте части моделей независимо от конфигурации и лицензий. Изменение runtime, модели или источника — отдельная проверка лицензии, CSP, размера и совместимости. При выпуске новой поставки пересоздайте `RELEASE_MANIFEST.json` командой `python scripts/verify-release.py --write-manifest`, затем проверьте его без флага. Изменение манифеста не заменяет проверку кода.

Новые свойства нельзя молча добавлять из генерации. Экспорт должен сохранять ручное подтверждение. Внешняя публикация требует отдельного реализованного подключения; переход по ссылке не считать успешной публикацией.

Лицензию собственного кода согласует правообладатель. Контакты и публичный SLA проекта не назначены.
