# Запуск и размещение

## 1. Переносимый локальный запуск

Python 3.10+; проверено на Python 3.12. Никаких дополнительных pip-зависимостей. Из корня:

```sh
python server.py
```

На Windows — `py -3 server.py` или `start.bat`. macOS/Linux — `sh start.sh`. Откройте http://localhost:8000. Сервер привязан к 127.0.0.1; не меняйте на 0.0.0.0 только ради открытия на своём компьютере. Альтернативный порт: `python server.py --port 8001`. Он создаёт отдельный origin браузера и отдельное локальное хранилище.

Проверка ответа (в Windows используйте curl.exe, если curl — псевдоним PowerShell):

```sh
curl -I http://localhost:8000/welcome.html
curl "http://localhost:8000/api/products?q=x"
```

Второй запрос должен вернуть JSON с кодом 400, без обращения во внешнюю базу.

## 2. Docker Compose

Установите Docker с Compose, запустите Docker Engine / Desktop. Из папки проекта:

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=50 pchelka
```

Откройте http://localhost:8000. Остановка: `docker compose down`. Обновление: заменить исходники, затем снова `docker compose up --build -d`.

Образ содержит только `public/`, `server.py` и базовый Python; pip/npm не используются. Модели MobileCLIP/Vosk остаются внутри образа. Контейнер непривилегированный, корневая FS read-only, capabilities удалены, действует no-new-privileges, лимит процессов и памяти. Healthcheck проверяет welcome.html, не доступность интернет-базы и не работу GPU.

Порт хоста ограничен `127.0.0.1:8000:8000`. Фотографии и каталог не хранятся в контейнере; volume для них не нужен. Удаление контейнера не удаляет каталог браузера. Смена домена/порта может сделать его недоступным под новым адресом — сначала экспортируйте резервную копию.

Для отдельной проверки образа:

```sh
docker build -t pchelka:local .
docker run --rm -p 127.0.0.1:8000:8000 --read-only --tmpfs /tmp pchelka:local
```

## 3. Сайт для внешних посетителей

Python http.server — сервер демонстрационного прототипа, не промышленный периметр. Публичное размещение требует HTTPS, обратного прокси, внешних лимитов, мониторинга и выбранного контроля доступа. Для банковского контура отдельно нужны меры из SECURITY.md. Публикация репозитория в GitHub не выполняет этот этап.

Сохраняйте same-origin маршрут `/api/products` и выдачу `.wasm` с типом `application/wasm`, `.bin` без преобразования, `.js/.mjs` с JS MIME. Не добавляйте политику CSP, которая блокирует необходимые Web Worker/WASM/WebGPU или разрешённые загрузки весов; текущие CSP находятся в HTML. Проверяйте их вместе с HTTP-заголовками прокси.

Не открывайте микрофон на обычном HTTP-домене: браузер требует HTTPS или localhost. Не обещайте бесплатность произвольного хостинга — условия зависят от площадки и нагрузки.

## 4. Сохранённый Node / Sites контур

Все исходники предыдущего размещения сохранены: Vinext, Cloudflare Worker, Vite, lockfile и настройки Sites. Они обслуживают тот же public/ и обработчик `app/api/products/route.ts`. Среда требует Node >=22.13, пакетный менеджер из package.json и доступ к реестру пакетов.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Используйте фактический адрес из вывода dev-сервера. `pnpm build` относится к этому контуру, не к Python. Конфигурация `vite.config.ts`, сервисные bindings и платформа доступа в `.openai/hosting.json` зависят от Sites. Не переносите доверие к `oai-authenticated-*` заголовкам в публичный сервер без соответствующего шлюза. Установка и этот маршрут сборки в GitHub-поставке повторно не проверялись; для независимого запуска используйте Python/Docker. В этой поставке нет автодеплоя, токенов Cloudflare или GitHub и созданной облачной инфраструктуры.
