# Контракт интеграции Пчёлки

Этот документ соответствует server.py, public/engine.js и интерфейсу текущей поставки. Старый контракт с OCR, SQLite и `/api/v1/drafts` сохранён только в docs/history и **не реализован** этой версией. API_TOKEN не нужен.

## Для владельца сайта: без API

В мастере подтвердите карточку → «Скопировать карточку для сайта» → вставьте в HTML-блок CMS. Фотография и стили уже включены. Можно скачать HTML и передать администратору. Статический результат не зависит от работающего сервера Пчёлки.

Не вставляйте весь HTML-документ внутрь другой страницы: для неё нужен блок `Bee.card`, а отдельный файл создаёт `Bee.html`. CMS может отфильтровать inline-стили/data URI. Тогда загрузите фото в медиатеку и замените src. Оплата, корзина, остатки и заказ не подключаются автоматически.

## JS API: локальный движок

Подключите копию `public/engine.js` на доверенной странице. [Минимальный пример](../examples/integration/README.md) работает с учебными данными.

```html
<script src="/engine.js"></script>
```

```js
const issues = Bee.check(model);
if (issues.some(issue => issue.type === 'block')) {
  // Показать сообщения и отправить пользователя к issue.step.
  return;
}
if (!explicitUserApproval) return; // отдельное действие человека
const cardBlock = Bee.card(model); // фрагмент <article>
const standalonePage = Bee.html(model); // документ HTML
const text = Bee.announcement(model, 'avito'); // 'youla' или 'vk'
const bytes = Bee.zip({'description.txt': text}); // Uint8Array; не HTTP-вызов
```

Низкоуровневые `card/html/zip` сами не выполняют бизнес-проверку или авторизацию. Обязательно вызывайте check и реализуйте явное подтверждение; интерфейс Пчёлки это делает. Не выдавайте готовность за официальный статус площадки.

Источник базы, если использован, передаётся как `internetSource` по существующей схеме интерфейса; не выдумывайте ссылки.

## HTTP API: только поиск сведений

`GET /api/products?q=…`, same origin. Спецификация OpenAPI 3.1: [public/api-contract.json](../public/api-contract.json), доступна по `/api-contract.json`. Самостоятельный Python не требует ключа. Режим доступа платформенного сайта может отдельно требовать вход.

```sh
curl --get --data-urlencode "q=название бренд" http://localhost:8000/api/products
curl "http://localhost:8000/api/products?q=3017620422003"
```

| Ответ | Смысл | Действие клиента |
|---|---|---|
| 200 | До 5 кандидатов; пустой products — нет совпадений | Сверить упаковку, показать источник, запросить подтверждение |
| 400 | Запрос вне 2–120 символов или неверный цифровой GTIN | Исправить запрос |
| 429 | 10 поисков в минуту на IP в текущем процессе/изоляте | Подождать, не зацикливать запросы |
| 503 | Источник/сеть не ответили или вернули неподходящий ответ | Заполнить вручную; не заменять отсутствующее догадкой |

Успешный ответ имеет `source`, `license`, `matched_by` (`barcode`/`text`), `query`, `retrieved_at`, `products`. В продуктах возвращаются только доступные поля фиксированного списка; все характеристики необязательны. Бренд не равен производителю; срок годности и хранение API не выводит из типа товара. Поиск названия не доказывает совпадение.

Сервер не принимает изображения, произвольный URL источника, промпт, пароль площадки или создание/хранение карточки. Нет `POST /api/v1/drafts`, webhooks, HTTP-генерации и серверной очереди. Для локальной классификации отдельный JS-интерфейс `PchelkaVision.classify`; для генерации и речи — соответствующие клиентские модули, а не HTTP API.

## Авито, Юла, VK

Текущий интерфейс формирует материалы для одного, выбранных или всех товаров: тексты, JPG, инструкция; для VK возможен общий пост. Продавец размещает их в своём аккаунте. ZIP не является обещанием совместимости с файлом массовой автозагрузки площадки. Нет OAuth, серверных токенов, автоматического статуса модерации или синхронизации цены.

Для будущей прямой интеграции нужны разрешённые возможности каждой площадки, регистрация приложения, токены в серверном хранилище, отдельное подтверждение публикации, журнал и обработка повторных запросов. Это не часть нынешнего контракта.
